01 // OVERVIEW

Language Introduction

Frisian / Farisan is an experimental programming language and security policy project initiated by Mamidi Nitesh. It investigates how security constraints—such as API authentication requirements, data sanitization rules, network egress boundaries, and autonomous AI agent permissions—can be treated as intrinsic language constructs rather than fragile afterthought middleware.

02 // PROBLEM STATEMENT

Motivation

In conventional backend and AI infrastructure development, security policies are scattered across framework decorators, reverse-proxy configs, and environment variables. A single missing decorator can expose sensitive endpoints or allow an AI agent to execute unauthorized tool calls.

Frisian / Farisan explores whether shifting security policy declarations directly into the language grammar and static analyzer can catch misconfigurations before deployment.

03 // CORE PILLARS

Language Design & API Security Principles (Planned / Research)

Secure-by-Default Declarations

Endpoints, external network calls, and file operations require explicit capability declarations in the planned specification.

First-Class API Contracts

Native syntax constructs for defining rate limits, token scopes, and schema validation rules alongside route handlers.

Deterministic Policy Analysis

Designed so the parser and static checker can audit permissions and generate a security manifest directly from source files.

AI Agent Sandbox Rules

Exploring syntax constructs to bound what external tools or APIs an autonomous LLM workflow is permitted to invoke.

Syntax Concepts & Code Examples (Conceptual Draft)

Below is an editable conceptual draft illustrating how Frisian / Farisan explores expressing security policies and API contracts. Edit this block as your grammar evolves: 

// [CONCEPTUAL SYNTAX DRAFT — PLANNED SPECIFICATION]
// File: api_gateway.frs

policy StrictAuth {
    require_header: "Authorization"
    scheme: "Bearer"
    rate_limit: 60 per minute
}

capability NetworkEgress {
    allow_hosts: ["api.internal.service"]
    deny_all_other: true
}

endpoint "/api/v1/analyze" uses StrictAuth, NetworkEgress {
    input payload: JsonSchema("ResumePayload")

    execute {
        // Planned runtime enforces StrictAuth prior to entry
        // and restricts outbound calls to allow_hosts
        sanitize(payload)
        return dispatch_analysis(payload)
    }
}
